## 1. この案件でやっていること

ゴルフ場のレストランで、お客さまが卓上のQRを読み、LINEの中から注文できる仕組みの試作。

- お客さま：卓上QR → LINE（友だち追加）→ 注文画面で伝票番号とメニューを選んで注文
- 厨房：iPadの厨房画面に、テーブルごとの伝票として並ぶ
- 提供後：「提供済み」を押した20分後に、LINEでアンケートが届く
- 決済はしない（従来どおり、レジで伝票番号に加算する）

先方に見せる紹介資料（アーティファクト）と、実際に動くアプリ（Cloudflare Workers）の2つがある。

## 4. 調べて分かったこと（アプリ本体）

Cloudflare の管理画面で確認した内容。

### コードはGitHubにない
- `700-order` も `line-harness` も、Cloudflareの「次のステップ」に「Gitリポジトリを接続してください」と出ている → GitHubとつながっていない
- パソコンから直接公開している。以前の作業はMacで行っていたので、**コードはMacにある可能性が高い**（未確定）
- このセッションから見えるGitHubのリポジトリは `starfollow` だけ（中身は画像仕様書のみ）

### `700-order` は画面を配るだけ
- 「静的アセットのみを扱うワーカー」と表示。データの保存場所（KV・D1・R2）はつながっていない
- 注文の受け取り、アンケート回答の保存などの処理は、ここにはない

### `line-harness` が裏側の本体（ほぼ確実）
- 過去24時間で約5,400回呼ばれている。トリガー（決まった時間に動く処理）が2つある
  - 「提供の20分後にアンケートを送る」処理がこれかもしれない（未確認）
- つながっている保存場所
  - D1データベース `line-harness`（テーブル90個、使用量 約1.6MB）
  - R2バケット（画像用）
  - Assets（画面のファイル。管理画面はおそらくこれ）
- トップのURLを開くと、LINEログイン（access.line.me）に飛んで 400 Bad Request になる
  → LINEアプリの外から直接開いたため。壊れているわけではない可能性が高い
- `/admin` を開くとログイン画面が出る → **管理画面はすでにある**

### `line-harness` はゴルフ場専用ではない
テーブルに「自動返信」「予約」「アフィリエイト」「広告」「配信」「イベント」などがあり、LINE公式アカウント運用の共通の仕組みと思われる。

アンケートに関係しそうなテーブル（ブラウザの自動翻訳で見た名前。英語名は推測）
- 「フォーム送信」（`form_submissions` ？）：フォームの回答が入る
- 「フォームを開く」（`form_opens` ？）：フォームが開かれた記録
- 「管理者ユーザー」：管理画面にログインする人

## 6. 次にやること（優先順）

1. **管理画面にログインし、ゴルフ場のアンケートの回答が見えるか確認する**
   - 見える → 管理画面は作らなくてよい。資料の「回答は管理画面に溜まります」もそのままでよい
   - 見えない → アンケート回答を `line-harness` に保存するようにつなぐ作業が必要
2. **AXEの公式LINEでデモできるか確認する**（資料のQRを読んでアカウント名を見る）
   - 別アカウントだった場合に必要なこと
     - AXEの公式LINEにつながるLINEログインのチャネルとLIFFを作る
     - アプリ側の設定（LIFF ID、メッセージ送信用トークン）を差し替える
     - 卓上QRを作り直す
     - 資料の中のQRとURLを差し替える
3. **コード本体をGitHubに上げる**（Macで作業）
   - これがないと、実際のLINEアンケートの変更（3問ずつ・最初から質問が届く形）ができない
4. **実際のLINEアンケートを、資料の見本と同じ形にする**
   - 「アンケートにご協力いただけませんか？」から始まり、3問ずつ届く
5. **紙のアンケートの実際の設問をもらい、資料とアプリの設問を差し替える**

## 7. 注意点

- **資料は「リンクを知っている全員」に公開中。** 変更はすぐに相手の画面にも出る。大きく変えるときは手元で確認してから公開する
- **資料に「回答は管理画面に溜まります」と書いてある。** ゴルフ場の回答が管理画面に届くことを確認するまでは、先方に約束しすぎないように注意する
- **管理画面やデータベースのスクリーンショットには、お客さまの回答やLINEのIDが写ることがある。** 共有するときは隠す
- 資料の料理写真はクラブのサイトから借りている。本番で使うなら許可が必要（資料の「入れていないもの」に記載済み）

## 8. 紹介資料の作業メモ

- 資料は1枚のHTML＋画像ファイルで、アーティファクトとして公開している
  - 画像：`img/hero.jpg`（メインビジュアル、1672×941）、`img/scene-*.jpg`（シチュエーション3枚、1200×900）、料理写真4枚
- メインビジュアルのPC向け配置は `@media (min-width:1001px)` の中にある
  - 文字の列：画面幅の36%、左から6%の位置
  - スマホの位置：文字の列から16%空けて置く
- アンケートの設問は、HTMLの最後の `<script>` の中の `PAGES` にまとまっている。差し替えはここを書き換える
  - 1ページ＝1枚のカード（3問ずつ）。`when` を付けた設問は条件を満たしたときだけ出る
