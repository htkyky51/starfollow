# Starfollow 画像仕様書

デザインシステム（Design System アーティファクト "Starfollow" / `project/`）から
抽出した、サイトに必要な画像の一覧と制約。画像を外部に発注・生成依頼する際は
このファイルをそのまま渡す。

---

## 1. 大原則 — 先に読むこと

デザインシステムの README に、画像に関する制約が明示されている。これを外すと
「別のスタジオのサイト」になる。

| ルール | 出典 |
| --- | --- |
| クライアント実績のスクリーンショットだけが写真。**ストック画像・イラスト・アイコンセットは使わない** | README / Imagery |
| **全面背景画像（bleed image）はどこにも置かない** | README / Imagery |
| 角丸なし・影なし・グラデーションなし・アクセントカラーなし | README / 冒頭 |
| 比率は **16/9・4/3・1/1 の3種のみ** | README / Imagery |
| 画像が未定の箇所はグレーボックスではなく **Placeholder ブロック**を出す | README / Imagery |

### 生成AIに頼めないもの

- **背景画像・抽象ビジュアル・イラスト** — 置く場所が設計上存在しない
- **アイコン** — システムはアイコンを持たない。`01` のモノ数字、`→`、46px×1px の
  罫線で代用する。やむを得ない場合のみ「22px ボックスに 1.4px ストロークの
  線画」を描き `assets/Icons` に追加する（アイコンライブラリの導入は禁止）
- **ヒーローの背景** — `<canvas>` でロゴの弧を15秒ループ描画＋46個のドリフト粒子。
  画像ではなくコードで実装済み
- **Cover** — インライン SVG で実装済み

### 生成AIに頼めるもの

- OG画像（§4）
- 実績が非公開の段階の**仮モックアップ**（§5）

## 2. 画像スロット一覧

すべての画像は `.fig` フレームに入る。
1px `rule` の枠 / `off` 地 / `object-fit: cover` / 角丸なし。

| # | 箇所 | 比率 | 推奨書き出し | 用途 |
| --- | --- | --- | --- | --- |
| A | WorkCard | 16 / 9 | 1600 × 900 | Works グリッドのサムネイル |
| B | WorkList | 4 / 3 | 1200 × 900 | Works 一覧行のサムネイル |
| C | InvertedSection（Golf） | 4 / 3 | 1200 × 900 | 1 : 1.15 分割の画像カラム |
| D | ケーススタディ本文（Prose） | 16/9・4/3・1/1 | 同上 | 本文中の図版 |
| E | OG画像 | — | 1200 × 630 | SNS シェア用 |

書き出しサイズはコンテナ上限 1320px からの逆算（2x 相当）。

### 注意：InvertedSection（C）の画像

`ink` 地（濃色）の上に載る。ここに入る Placeholder は `ink-raised` 地 +
`rule-on-ink-strong` 枠に切り替わる仕様なので、**明るい画像を置くと分離しすぎる**。
暗めの画面か、枠のコントラストを確認してから採用すること。

デザインシステムの「What this system does not contain」に、
`public/works/` のクライアント実績スクショ5点がクライアント所有物として
除外されている旨の記載がある。**ここに入るのは実物のスクリーンショット。**

| 実績 | 業種ラベル | 必要画像 | 備考 |

## 4. OG画像（1200 × 630）

システムに規定がない唯一の実需。ただし **Cover のインライン SVG がそのまま使える**
ので、新規生成より流用を推奨する。

Cover の構成（`project/components/Cover/preview.html`）:

- `paper` 地に `ink` の縦スラブ 216×320、右へ 148×190 / 148×129 / 114×114 / 114×205 が階段状に配置
- 弧（ロゴのモチーフ）を `paper` 色 1.4px ストロークで横断させ、左下に星
- 左に `Starfollow`（Schibsted Grotesk 700 / 64px）とタグライン「価値を共創し、共に未来へ」

960×320 で描かれているため、1200×630 へは再レイアウトが必要。

## 5. 仮モックアップを生成する場合

実績がまだ公開できない段階の埋め草として生成画像を使うなら、以下を厳守する。

- 必ず `.fig` フレーム（1px 枠 / 角丸なし）に入れる
- 比率は 16/9・4/3・1/1 のいずれか
- **実在の事例に見える形で公開しない**
- グラデーション・影・角丸・彩度の高い色を含めない

### 発注プロンプト雛形

> 日本語のコーポレートサイトのスクリーンショット風モックアップを作成してください。
> デザインは Swiss editorial スタイル：白地（#fbf7f1 系）に黒（#14181F）、
> アクセントカラーなし、グラデーションなし、影なし、角丸なし。
> 罫線（1px ヘアライン）と余白だけで階層を作る。
> 日本語本文は行間 1.95〜2.15 と広め。見出しは Noto Sans JP、
> ラベルは英字大文字のモノスペース。
> 比率は 16:9、書き出し 1600×900。写真やイラストは含めないこと。

## 6. 結論 — いま足すべきもの

**背景画像を増やす方向ではなく、Placeholder が刺さっている枠に実物を入れる。**

Placeholder は「未完成でもデザインとして読める」ための仕組み（45度ハッチ＋
何が入るかをモノ書体で自己申告）なので、現状は破綻ではなく想定内の中間状態。

視覚的な厚みを足したい場合、このシステムの唯一の強調手段は
**`ink` 地の InvertedSection を1ページに2〜3回使うこと**。
3回を超えると強調ではなくテーマになるため使いすぎない。
